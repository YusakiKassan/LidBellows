# 风箱模型和手感参数

代码在 `Sources/BellowsCore/Bellows.swift`，参数都在 `Bellows.Tuning` 里。

## 计算过程

每 1/120 秒做一次：

1. **测速**：对最近 0.25 秒内的角度读数做最小二乘直线拟合，斜率就是角速度（°/s，拉开为正）。
   传感器只有约 10 Hz，相邻两点相减会很抖；拟合能同时压住刷新慢和静止抖动这两个问题。
   如果超过 0.16 秒没有新读数，就认为屏幕停在最后一次读到的位置，
   在当前时刻补一个同角度的点参与拟合，于是速度会自然降到 0。
2. **判断方向**：速度超过死区才算开始一次推拉，降到死区一半以下才算停下（施密特触发），
   避免在零点附近来回跳。新一次推拉方向与上一次相反时，报告一次换向（触发“换风”重音）。
3. **算目标风压**：
   `level = clamp((|速度| − 死区) / (满风压速度 − 死区), 0, 1)`，
   `目标 = level ^ curve`。按住空格时目标至少为 0.6。
4. **风压追随目标**：
   - 目标更高：以 `attack` 为时间常数快速上升；
   - 目标更低、屏幕还在动：以 `tail / 3` 为时间常数回落；
   - 目标更低、屏幕已停：先保持 `hold` 秒不变，之后以 `tail / 3` 为时间常数漏气。

   指数衰减经过 3 个时间常数降到约 5%，所以 `tail` 就是“漏到 5% 所需的秒数”。

## 参数

| 参数 | 默认 | 界面 | 含义 |
|---|---|---|---|
| `fullSpeed` | 45 °/s | 灵敏度 | 达到满风压的屏幕速度。界面上的灵敏度 s ∈ [1, 10]，`fullSpeed = 135 / s`，默认 s = 3 |
| `hold` | 0.4 s | 换向保持 | 屏幕停住后风压保持不漏的时间，0–1 s |
| `tail` | 1.5 s | 余气 | 风压漏到 5% 的时间，0.3–4 s |
| `deadzone` | 2 °/s | 自动 | 低于此速度不出风。只能读整度的传感器自动改成 12 °/s |
| `curve` | 0.6 | — | 速度到风压的曲线，小于 1 让轻柔的动作更早出声 |
| `attack` | 0.04 s | — | 风压上升的时间常数 |
| `window` | 0.25 s | — | 测速拟合用的时间窗 |
| `staleAfter` | 0.16 s | — | 多久没新读数算屏幕停住 |
| `gap` | 0.5 s | — | 读数间隔超过此值（比如睡眠后）就丢掉历史重新测速，不把它当成一次猛拉 |

界面上的三个设置存在 `UserDefaults`（域 `io.github.yusakikassan.lidbellows`），删掉即可恢复默认：

```sh
defaults delete io.github.yusakikassan.lidbellows
```

## 怎么调

| 感觉 | 调整 |
|---|---|
| 要推很大幅度才响 | 提高灵敏度 |
| 轻轻碰一下就很响 | 降低灵敏度 |
| 换方向时声音断掉 | 增加换向保持 |
| 停手后声音拖太久 | 减少换向保持和余气 |
| 静止时有声音 | 传感器抖动超过死区，提高 `deadzone` 并在 issue 里报告你的机型 |

改了模型的行为，请同时更新 `Tests/BellowsCoreTests/BellowsTests.swift` 里相应的测试，
这些测试把手感钉住，防止重构时悄悄变了。
